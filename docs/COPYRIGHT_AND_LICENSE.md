# Copyright and License Policy

## Public-repository decision

Do not add a license automatically. Rahul must explicitly choose one of:

1. leave the repository without a license;
2. apply one license to code and educational notes;
3. license code and educational notes separately.

Before proposing a license, explain permissions, attribution, redistribution, modification, commercial use, patent terms when relevant, warranty/liability, and whether the terms fit code, prose, diagrams, data, or all of them.

Public visibility alone does not grant broad reuse rights.

## Original educational material

Write explanations, diagrams, examples, tests, variations, and exercises in original language. Do not recreate a textbook, paid course, article, editorial, private interview set, or proprietary repository.

Short quotations are allowed only when exact wording matters and attribution is clear. A citation does not make extensive copying acceptable.

## External code

Before reusing code, identify its license, confirm the intended use is permitted, preserve required notices, and prefer a small original implementation. Do not reuse code with missing, unclear, or incompatible terms.

## LeetCode and interview content

Do not copy complete problem statements, paid editorials, hidden tests, premium material, company-tag datasets presented as hiring truth, leaked questions, or private interview content. Store official links and minimal metadata, then write original pedagogical notes and variations.

## Privacy and confidentiality

Never commit credentials, personal/medical/relationship data, production logs, customer data, employer-confidential code, proprietary datasets, or restricted take-home material. Use synthetic inputs and names.

## License-change procedure

A license change requires explicit owner approval, clear path coverage, third-party-material audit, consistent README notices, and required attribution. No `LICENSE` file belongs in the bootstrap.
